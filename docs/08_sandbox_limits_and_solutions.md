# Sandbox limits and our solutions

A free personal sandbox lacks some things a paid company instance has. Each gap is solved inside the project, so the case study is complete.

| What the sandbox lacks | Our solution | What it shows | Stage |
| --- | --- | --- | --- |
| The online Content Service that keeps software names current | The content library shipped with the product, the system's suggestions, and manual cleaning; the rate is measured before and after | We understand how normalization works instead of relying on a black box | 3 |
| Scanning tools that find installed software | A script that creates the same records a scan would | How the data model fits together | 2 |
| Agents that measure software usage | A script that adds realistic usage records | How reclamation decides what is unused | 5 |
| SaaS License Management | The Acrobat subscription with its renewal date | Subscription tracking without a cloud integration | 4 |
| A guaranteed Software Asset Workspace | A known install path and repair steps, with the classic menus as fallback | Platform troubleshooting | 1 |
| Ready-made analytics data | Starting the analytics jobs, or six standard reports on one dashboard | Reporting that works without extra licenses | 6 |
| Outbound email | Reclamation with user notification switched off | The approval flow, without sending mail | 5 |
| Permanence: unused sandboxes are deleted after 10 days | A weekly sign-in by the sandbox owner, plus a tested backup | Recoverability | 0, 6 |
| Now Assist AI features | Described as a production enhancement in the case study | Awareness of the roadmap | 7 |
| More than one sandbox per account | One owner holds the sandbox; team members get their own logins inside it | Access control | 1 |

## What does not change

The core of SAM Professional is fully present: discovery models, normalization, software models, entitlements, allocations, the reconciliation engine, the Microsoft publisher pack, reclamation rules, removal candidates and the Software Asset Workspace.
